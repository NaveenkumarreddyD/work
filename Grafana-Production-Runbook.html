TLS terminates on Grafana at port 443. Users connect directly to the host, so there is no proxy or load balancer in the path.

Using this runbook

Run one block at a time and compare against the Expect: line. Steps marked CHECK must pass before continuing.

Do not run this file as a script. It reboots the host at Step 5 and waits on external input at Steps 9, 11 and 34.

Prerequisites

  1. The eight values in Step 1.
  2. A DNS record for the Grafana FQDN, requested in Step 9.
  3. A TLS certificate for that FQDN. Step 10 generates the CSR, Step 11 requests it, Step 12 installs it.

Request the DNS record before the certificate. The certificate is issued against the DNS name, so the name has to be settled first.

Phase 3: DNS and TLS certificate

Do this phase first. Grafana will not start without the certificate, and the DNS and certificate requests are the longest lead times in the install. Steps 13 to 34 do not depend on either, so get both requests moving and carry on working.

Apply settings

Set authentication rules

pg_hba.conf is first-match-wins. RHEL ships host all all 127.0.0.1/32 ident above anything appended, so appended rules are never reached. The commands below insert the grafana rules above the first host rule and convert the loopback ident defaults to scram-sha-256. The local socket rule stays peer, so sudo -u postgres psql continues to work.

authentication rulesCHECK

Allow Grafana to bind port 443

Grafana runs as the unprivileged grafana user, which cannot bind a port below 1024 without this capability. Do this before the first start.

First confirm nothing else already holds the port.

ExpectOK: port 443 free. If httpd or nginx is listening, stop and disable it, or keep Grafana on a high port instead.

ExpectAmbientCapabilities=cap_net_bind_service.
